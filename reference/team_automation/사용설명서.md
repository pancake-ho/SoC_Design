# EE470 V8 조원용 자동화

PC에서 자기 RTL을 번호가 붙은 압축으로 만든다. dice에서 번호만 지정해 실행한 뒤, 서버 결과 압축을 PC로 가져오면 HTML과 JSON에 여러 시도의 비교가 누적된다. 압축을 푼 `ee470_v8_team_kit` 폴더에서 PC 명령을 실행한다.

## 1. 각자 준비할 것

| 항목 | 각자 입력할 값 |
|---|---|
| V8 원본 | 교수님이 배포한 깨끗한 V8 `baseline_release` 폴더 |
| RTL | 이번 시도의 소스만 담은 RTL 폴더 전체. V8 top·모듈·포트·메모리 규약과 공통 프로파일을 사용하는 설계 |
| 팀 이름 | 결과에 표시할 임의의 영문·숫자 식별자. 예시는 `TEAM01` |
| 서버 위치 | 각자 dice 계정의 홈 아래 작업 폴더. 아래에서는 `~/ee470_work` 사용 |

PC Python 3.9 이상, dice의 Bash·Python 3와 수업용 EDA 큐가 필요하다. 공유 ZIP에는 교수님 배포본과 팀의 개인 설계·결과가 들어 있지 않다. 각자 받은 배포본을 지정한다. 원본 해시가 맞지 않으면 패키징을 중단하므로 V7, 수정한 공통 TB, 이미 작업한 합성 폴더를 V8 원본으로 지정하지 않는다.

## 2. PC에서 실행 패키지 만들기

아래는 Windows PowerShell 예시다. 따옴표 안의 두 경로와 팀 이름을 자기 값으로 바꾼다. `01`은 이번 시도 번호다.

```powershell
python make_try.py 01 --release-root "D:/course/v8/baseline_release" --rtl-root "D:/my_team/try01/rtl" --team-id TEAM01
```

`01.tar.gz`가 생긴다. 다음 시도는 번호와 RTL 경로를 바꾼다. 이미 만든 번호의 파일은 보존한다. 원하면 `--output-dir "D:/my_team/packages"`로 PC 저장 위치를 지정할 수 있다.

기본 범위는 **F01–F12 → DC NXT 합성 → 6개 시나리오 setup·hold**다. 다른 범위가 필요하면 패키지를 만들 때 `--through functional`, `--through gate`, `--through power` 중 하나를 지정한다. `gate`는 STA 판정을 통과했을 때 6개 시나리오에서 SDF F12를 실행한다. `power`는 gate 통과 후 PrimeTime 전력 보고서도 만든다. 전력 모델·활동도·단위의 확인이 필요하며 최고 검증 주파수 검색은 별도다.

## 3. dice에서 실행

MobaXterm으로 각자 자기 계정에 접속한다. 최초 한 번만 실행 폴더를 만든다.

```bash
mkdir -p ~/ee470_work/{packages,results}
```

MobaXterm SFTP로 이 ZIP의 **`run_try.sh`**와 만든 **`01.tar.gz`**를 둘 다 `~/ee470_work/packages/`에 올린다. 교수님이 안내한 사용 시간에 연결된 터미널에서 실행한다.

```bash
bash ~/ee470_work/packages/run_try.sh 01
```

```text
~/ee470_work/
  packages/  run_try.sh, 01.tar.gz
  results/
    01/      work/, 01_evidence.tar.gz
    02/      다음 시도를 위해 생성한 빈 폴더
```

실행 중에는 터미널을 유지한다. 수업 공용 큐에서 한 작업씩 실행한다. `RESULT_ARCHIVE=`가 나오면 거기에 표시된 압축을 PC로 내려받는다. 기능 실패나 타이밍 위반이 있어도 생성된 로그와 보고서를 가져온다. 기존 번호의 작업 폴더가 있으면 다음 번호를 사용한다. 다음 시도부터는 새 `NN.tar.gz`를 올리고 명령의 숫자만 바꾸면 된다.

## 4. PC에서 결과 확인

```powershell
python local_tools/review_results.py "D:/my_team/01_evidence.tar.gz" --try-name try01 --change "비교 기준용 첫 실행"
```

- `reports/index.html`을 브라우저에서 열면 최신 실행 상세와 같은 조건의 전체 비교표를 볼 수 있다. 원본 로그와 보고서 링크도 포함된다.
- `reports/server_compare.json`에는 최신 실행 지표, 직전 시도와의 변화, 동등한 조건에서의 순위가 들어 있다. F01 CPU 구간, F12 전체와 CNN 사이클, SRAM 읽기·쓰기·요청 대기·응답 지연, setup·hold, 면적을 확인할 수 있다.
- `server_results/`에 분석용으로 푼 사본을 보관한다. 각 결과 압축을 같은 도구로 가져오면 비교표가 갱신된다. 미측정 항목은 빈 값으로 남는다.

## 기준 유지와 오류 확인

- 공식 기능 확인은 교수님 V8 테스트벤치·입력 생성·기대값을 사용한다. 이 실행기는 공개 시험과 결과 정리를 돕고, 학점과 공식 순위는 수업 채점 절차를 따른다.
- 공통 10 ns ideal clock, latency, I/O delay, uncertainty, load, timing 예외를 유지한다. 합성에서는 공용 SAED32 NDM을 읽고, 사용자가 소유한 실행 폴더에 산출물을 저장한다.
- `NEEDS_TIMING_FIX`이면 `sta_summary.json`과 `source/synth/reports/`의 setup·hold 보고서를 본다. 공통 제약은 유지한 채 팀 RTL이나 허용된 합성 최적화로 보정한다. hold 보정은 각 팀 회로와 결과에 맞춰야 한다.
- `RESULT_ARCHIVE=`가 뜨기 전에 멈추면 터미널 오류와 `results/NN/work/` 안의 로그를 먼저 확인한다.
